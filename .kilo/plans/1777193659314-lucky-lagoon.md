# Register Page Implementation Plan

## Overview
Add a registration page (/register) that allows new users to create accounts via email/password and social providers (Google, GitHub, Discord). The backend already uses Better-Auth which supports registration out of the box - we need to expose the frontend route and ensure the API endpoints are properly accessible.

## Current Architecture
- **Authentication**: Better-Auth with Drizzle adapter (PostgreSQL)
- **Frontend**: TanStack Router, React, Tailwind CSS
- **Auth Client**: `authClient` from `better-auth/react` in `frontend/src/lib/auth.ts`
- **Existing Login Page**: `/login` route with email and social login support
- **Profile Creation**: Post-login onboarding flow (`/onboarding`) creates a profile record

## Backend - Existing Auth API (Better-Auth)
Better-Auth already provides these endpoints (exposed via OpenAPI plugin in `auth.config.ts`):
- `POST /api/auth/sign-up/email` - Email/password registration
- `POST /api/auth/sign-in/email` - Email login
- `POST /api/auth/sign-in/social` - Social login (Google, GitHub, Discord)
- `POST /api/auth/sign-out` - Logout
- `GET /api/auth/session` - Get current session

No backend changes needed - Better-Auth handles registration automatically.

## Security Considerations

- Social logins use OAuth flow with trustedOrigins
- Session cookies are secure (SameSite, Secure in production)
- Registration page prevents authenticated access
