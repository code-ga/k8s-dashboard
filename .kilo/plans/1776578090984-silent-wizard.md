# Plan: Fix Route Validation and PVC Owner Mapping Issues

## Problem Summary

1. **Unstrict validation in routes**: Users can submit invalid data (e.g., empty `image` in deployments) that passes API validation but fails in Kubernetes.
2. **PVC owner mapping bug**: PVC creation doesn't create a DB record first - it directly sends commands to the agent, causing ownership to be missing ("default-account" issue).

## Root Cause Analysis

### Issue 1: PVC Route (`backend/src/routes/pvc.ts`)
- **Current behavior**: Direct command to agent without DB record (lines 97-117)
- **Expected behavior**: Create DB record first with `ownerId`, then send command (like `pod.ts` pattern)
- **Impact**: PVCs have no owner tracking, causing sync/ownership issues

### Issue 2: Deployment Route (`backend/src/routes/deployment.ts`)
- **Current behavior**: `image: Type.String()` accepts empty string (line 650)
- **Expected behavior**: `image` should have `minLength: 1` validation
- **Impact**: Invalid deployments can be created in DB

## Implementation Plan

### Task 1: Fix PVC Route (High Priority - Bug Fix)
**File**: `backend/src/routes/pvc.ts`

1. Add `import { eq, type InferInsertModel } from "drizzle-orm"`
