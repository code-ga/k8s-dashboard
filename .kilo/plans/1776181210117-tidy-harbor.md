# Authentication Migration: Cookie to Header-Based Token

## Goal
Migrate from cookie-based authentication to Bearer token authentication using better-auth's `bearer` plugin to solve cookie issues.

## Architecture

Using better-auth's official Bearer Token plugin:
1. Backend adds `bearer()` plugin to auth config
2. On successful sign-in, backend returns token in `set-auth-token` response header
3. Frontend captures token via `onResponse` callback (not `onSuccess`)
4. Frontend stores token and includes in all API requests via `fetchOptions.auth`
5. Backend middleware already supports header-based auth via `auth.api.getSession({ headers })`

## Changes Required

### 1. Backend Changes

#### 1.1 `backend/src/libs/auths/auth.config.ts`
- Add `bearer` plugin from `better-auth/plugins`
- Configure CORS to expose `set-auth-token` header to frontend

#### 1.2 `backend/src/middleware/auth.ts`
- **No changes needed** - already uses `auth.api.getSession({ headers })` which works with Bearer tokens

#### 1.3 WebSocket Routes (`backend/src/routes/pod.ts`, `deployment.ts`)
- No changes needed - `roleAuth` already passes headers to `auth.api.getSession()`

### 2. Frontend Changes

#### 2.1 `frontend/src/lib/auth.ts`
- Add `onResponse` callback to capture `set-auth-token` header
- Store token in localStorage
- Configure auth client to use Bearer token in requests

#### 2.2 `frontend/src/lib/api.ts`
- Add `Authorization: Bearer <token>` header to all treaty requests via custom fetch
- Remove `credentials: "include"` (cookies no longer used)

#### 2.3 Frontend WebSocket Connections
- **Files**: 
  - `frontend/src/routes/dashboard/cluster$id/pods$podId.tsx` (line 959)
  - `frontend/src/routes/dashboard/cluster$id/deployments$deploymentId.tsx` (line 1040)
- Pass token via WebSocket subprotocol: `new WebSocket(url, ["Bearer", token])`
- Backend reads from `Sec-WebSocket-Protocol` header during upgrade

### 3. Agent Auth (No Changes)
- Agent uses `Authorization: Bot <token>` header - keep as-is

## Implementation Order

1. **Backend**: Add `bearer()` plugin to `auth.config.ts`
2. **Frontend**: Update `auth.ts` to capture and store token
3. **Frontend**: Update `api.ts` to include Bearer token in requests
4. **Frontend**: Update WebSocket connections to pass token
5. **Test**: Verify login, API calls, and WebSocket connections work

## Key Code Changes

### Backend (auth.config.ts)
```typescript
import { bearer } from "better-auth/plugins";

export const auth = betterAuth({
  plugins: [openAPI(), bearer()],
  // ... rest unchanged
});
```

### Frontend (auth.ts)
```typescript
export const authClient = createAuthClient({
  baseURL: `${BACKEND_URL}`,
  fetchOptions: {
    onResponse: ({ response }) => {
      const authToken = response.headers.get("set-auth-token");
      if (authToken) {
        localStorage.setItem("bearer_token", decodeURIComponent(authToken));
      }
    },
    auth: {
      type: "Bearer",
      token: () => localStorage.getItem("bearer_token") || "",
    },
  },
});
```

### Frontend (api.ts)
- Add Authorization header with Bearer token to all treaty requests

### Frontend WebSocket
```typescript
const token = localStorage.getItem("bearer_token");
ws = new WebSocket(
  `${protocol}//${backendUrl.host}/api/pods/${clusterId}/logs/${pod.id}?container=${selectedContainer}`,
  ["Bearer", token || ""]
);
```
