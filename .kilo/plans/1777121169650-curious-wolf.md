# Fix TypeBox Schema Validation Error - Malformed Regex Patterns

## Issue Summary
The k8s-dashboard backend is failing to start with a TypeBox schema compilation error:
```
error: Preflight validation check failed to guard for the given schema
```

## Root Cause
Multiple TypeBox schema definitions in `deployment.ts` and `pod.ts` contain malformed regex patterns. The pattern `"^[.*\\S.*$"` is missing a closing `]` bracket for the character class. It should be `"^.*\\S.*$"`.

## Affected Files
1. `backend/src/routes/deployment.ts` - Lines with cpu/memory/resource regex patterns and env name/value patterns
2. `backend/src/routes/pod.ts` - Similar regex pattern issues

## Changes Made

### deployment.ts
- Fixed all occurrences of `pattern: "^[.*\\S.*$"` → `pattern: "^.*\\S.*$"`
- This affects:
  - CPU/memory resource request/limit fields (lines ~706, 709, 716, 719)
  - Update patch body CPU/memory fields (lines ~1105, 1108, 1115, 1118)
  - ConfigMap/Secret ref name fields (lines ~1142, 1146, 1148, 1157, 1167, 1171, 1175, 1182, 1186, 1203, 1207, 1209, 1218, 1228, 1232, 1236, 1243, 1247, 1260, 1263, 1270, 1277, 1278)
  - Env name/value fields in update body (lines ~1127, 1129)
  - Command/args array string patterns (lines ~1260, 1263)
  - Port name fields (line ~1270)
  - Annotation record key/value patterns (lines ~1277, 1278)

### pod.ts
- Fixed all occurrences of `pattern: "^[.*\\S.*$"` → `pattern: "^.*\\S.*$"`
- This affects similar fields for pod resources, config maps, secrets, etc.

## Verification
After applying fixes, the TypeBox schema should compile correctly when the application starts, and validation errors should be properly returned to users as JSON responses instead of causing server startup failures.

## Additional Issue Identified
The error response from TypeBox/Elysia needs to be caught and returned as a proper user response. Currently, the validation error at line 629-630 in deployment.ts throws a `TypeCompilerTypeGuardError` which is not caught and formatted as a user-friendly response. This should be wrapped in a try-catch to return a 400 Bad Request with the validation error details.
